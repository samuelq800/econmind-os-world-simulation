# Season 1 public country read boundary

The interactive country page reads the selected `BALANCED_2026_09_28_V1` country file first. It never derives Office permission from `?role=` or `?country=`; those parameters select only public geography and local planning views. A local decision remains `LOCAL_NOT_EXECUTED`.

An embedding host may set `window.__ECONMIND_WORLD_READ_CONFIG__ = { apiBaseUrl: 'https://…/functions/v1/world-v2-official-read/' }` before `country-context.js` loads. The base preserves the exact merged Edge function prefix when appending `v1/world-data/...`. A standalone API root is also accepted; the legacy `{ apiOrigin: 'https://…/' }` contract remains root-only. Supplying both config keys is invalid. Do not put a token, service key, World identity or API base in the page URL. The adapter sends credential-free GET requests. A's reviewed first country contract is `official-country-baseline-v1` with `dataNature: OFFICIAL_SELECTED_SOURCE_DATASET`, package ID, both selection and country-source hashes, `sourcePath: data/countries.json`, country ID, units, `proposalFieldsAreExecuted: false`, `liveWorldState: false`, and the selected source `country` record. It does **not** include scene art, facilities, deposits, opening finance, or a World projection. The adapter verifies the shared country fields against the published static package and continues to render facilities/resources only from that package.

## Publication handoff

After E verifies the real HTTPS endpoint and exact Pages-origin CORS, the release executor can set the public repository variable `WORLD_OFFICIAL_READ_BASE_URL` to that verified function base. The existing Pages build passes it to `scripts/configure-official-page-read.mjs`. Local preview builds can pass the same non-secret environment variable. No project hostname is inferred or hardcoded, and no repository variable is provisioned by this code change.

The script injects a frozen config into the **built** `dist/season1-immersive/index.html` immediately before the country adapter. All six roles and all 70 country entry redirects use this one page. Source HTML, the owner-selected UI archive, country numbers, site/resource IDs and maps are unchanged. Absent/empty config leaves the build disconnected; malformed, credential-bearing or wrong-function config fails the build before publication. Reconfiguration replaces the old injection, including removing it when disabled. The CLI reports `CONFIGURED_READ_ONLY`, not a connectivity or live-state claim.

The 34-dataset drawer uses the same base. API reads use `cache: no-store`; session catalogues are not persisted. Country changes, catalogue refresh/failure and invalid/unavailable dataset responses retire the previous catalogue. Requests retired by country changes are aborted and cannot repopulate it. A replacement endpoint requires a new page build/reload and a new session; no catalogue or rows are shared between sessions.

Required release readback remains separate: confirm the deployed page's injected base, country detail matching bundled source, catalogue of 34, country-filtered exact-decimal rows, source hashes and units, unavailable/mismatch fallback, and CORS from the actual Pages origin. `tests/world-web/official-page-config.test.ts` exercises the generated config through the browser adapter and the **actual merged Edge handler DTOs** backed by immutable repository source bytes, without any network/database access. This verifies code compatibility, not production connectivity. Leave the publication variable unset until E verifies the endpoint.

State labels are explicit: `STATIC_BASELINE` (bundled selected data), `API_COUNTRY_VERIFIED` (country source record confirmed by the public API; bundled sites/resources remain separately sourced), `STATIC_DISCONNECTED` (API unavailable/mismatched, bundled data retained), and `MISSING` (no valid selected country data, no substitute numbers). Every result has `runtime: NOT_CONNECTED`. The selected package is source data, not an OpeningSeed commit, live WorldVersion, executed facility, or command receipt. A separate authorized projection adapter can be added only after an authenticated, scope-bound API contract exists; this public adapter must never reinterpret a proposal or URL role as runtime authority.
