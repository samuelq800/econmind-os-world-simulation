# 02｜规范冲突与待批准架构决定

本表不是对规范的擅自修订。每项推荐方案均为PROPOSED_NOT_APPROVED；缺少批准时，只阻塞受影响实现，其他无冲突的审计纠偏、权限补丁、回归基础可并行开展。原始Word保持不改。

## 最早需冻结的六项

ADR-01阶段/编号，ADR-02唯一owner，ADR-03时钟，ADR-04日内读值，ADR-05在途与所有权，ADR-09审批。财务/国民核算扩大之前必须补齐ADR-06/07/08。

## ADR-01｜统一规范优先级与引擎/阶段编号

依据：Master §0/§4及Engine 01–18；Constitution §0/§6/§17

**问题：**Master把Time/Event列E01、NationalAccounts/Risk/Scoring列E18，日结18阶段；Constitution日结15阶段，公共服务/家庭顺序不同且银行等有合并。不能把18个Engine误认成18个一对一phase，也不能凭标题判其中一份自动覆盖全部另一份。

**建议裁决：**保留Master的18个Engine ID；以Master18阶段为协调基线，建立phase→engine operation映射；Constitution的硬约束不降级，差异用批准的协调附录明确。修改任何phase语义需新ADR。

**受影响工作包：**P02, P04, P09, P19

批准记录：owner / 日期 / 规范版本 / 理由 / 替代方案 / 必增测试。

## ADR-02｜逐字段唯一owner及交接协议

依据：Master E03/E04/E08/E09/E10/E12/E13/E15/E16/E17/E18；Constitution §4/§17及AppendixB

**问题：**skill、inventory、facility capacity、household deposits、FDI/foreign debt、money aggregates等在不同文档描述有重叠；多模块读取/发命令不能变为多表独立权威写。

**建议裁决：**固定canonical entity owner与posting service：Education发毕业事件给Labour；Project发commission事件给设施owner；Production提交库存消耗命令给Inventory；家庭deposit读银行同一账户/工具；跨国合同创建权利义务但余额归对应账本。所有影子字段标projection并测试不能回写。

**受影响工作包：**P02, P06, P08, P10, P12, P17

批准记录：owner / 日期 / 规范版本 / 理由 / 替代方案 / 必增测试。

## ADR-03｜360模拟日历、暂停与命令/日结交界

依据：Master §2/E01/AppendixB；Constitution §5/R019–R024；current 2h clock source

**问题：**10×已明确，但当前12×及real day期限与新规则不一致；命令紧贴日界/暂停到期/worker迟到的处理需要固定。

**建议裁决：**经济时间使用自world起点的sim ticks，year=360days；现实日期只用于审计和单一clock锚定；暂停排除elapsed；恢复按应有日界/事件顺序补算；明确command acceptance cutoff及相同sim时点优先序；旧期限迁移保留原语义或经批准显式转换。

**受影响工作包：**P04, P05, P15

批准记录：owner / 日期 / 规范版本 / 理由 / 替代方案 / 必增测试。

## ADR-04｜当期/期初/滞后读值与资源循环

依据：Master §4 settle order和各Engine reads；Master E08/E09/E10/E03/E13/E14

**问题：**资源开采在能源之前、生产在劳动力之前、家庭消费在财政日结之前；若随意读取当日尚未产生的结果，将造成循环、预支能量/工资/福利或下游反写。

**建议裁决：**为每个输入标opening/current_phase/prior_day/scheduled_event；日内固定劳动/能量预算的来源，禁止当日免费递归循环；工资税费区分应计与已付；只让已到账现金进入可支配现金。并将resource extraction唯一物理产出与Production统计映射区分，不能双采。

**受影响工作包：**P08, P09, P12, P13

批准记录：owner / 日期 / 规范版本 / 理由 / 替代方案 / 必增测试。

## ADR-05｜在途货物、所有权及国民账户确认时点

依据：Master E08/E16/E18；Constitution R075/§8/AppendixD

**问题：**“库存”“在途”“Delivered/ownership-transfer”“exports delivered”的表述需要同一物理边界；发货扣卖方后不能没有transit ledger，也不能到货再次扣减。

**建议裁决：**明确physical location、reservation、ownership、risk bearer、economic recognition四个字段；每次dispatch/transit loss/delivery分别守恒；选定合同默认title转移时点并与X/M一致；部分交付逐批次事件，未到货不得成为进口方可用投入。

**受影响工作包：**P06, P07, P16, P17, P19

批准记录：owner / 日期 / 规范版本 / 理由 / 替代方案 / 必增测试。

## ADR-06｜商品目录和完整经济供给/核算的闭合缺口

依据：Master AppendixA1/A2及E03/E05/E10/E13/E18；Social药品采购；Constitution §24 fixed registry

**问题：**12种可交易商品含GRAIN，12production sectors没有农业；家庭服务/建设/医疗耗材和公共服务的供给、价格与核算也不能仅凭工业商品目录自动推得。

**建议裁决：**提交非全球现货目录的domestic sector/service/subledger映射方案，补清农业、服务、建设及医药耗材的生产/采购/成本来源；不得静默新增第13全球商品或随机补粮，也不得仅假定库存永远够用。若确需变更固定registry必须批准变更。

**受影响工作包：**P02, P09, P11, P12, P19, P22

批准记录：owner / 日期 / 规范版本 / 理由 / 替代方案 / 必增测试。

## ADR-07｜建设期间增加值与完工不直接加GDP

依据：Master E12 capital formation rule；Constitution R055

**问题：**Master规定当日已完成施工价值进入capital formation；R055“GDP只能在后续生产/服务中产生”的措辞可能排除真实施工产出。

**建议裁决：**协调为：批准/付款/commission本身不加GDP buff；真实施工活动按材料中间投入、劳动和产出记录建设增加值/在建资产，后续运营另记产出，避免重复计算。需批准澄清文本，不自动改宪法。

**受影响工作包：**P10, P19

批准记录：owner / 日期 / 规范版本 / 理由 / 替代方案 / 必增测试。

## ADR-09｜不同文件审批要求、阈值与自身签字

## ADR-11｜幂等重复响应与并发审批重放

依据：Constitution R027–R032及AppendixE；Master E01

**问题：**AppendixE不允许重复命令被“自动降级为成功”；工程上重试需分清原已完成结果与新执行，不能用同key覆盖新payload。

**建议裁决：**定义command_id+payload_hash唯一性；原结果用明确ALREADY_PROCESSED/receipt返回且executed=false，不伪造新成功；同key异payload拒绝；consumer receipts独立于append-only事件，避免为processed_at UPDATE历史event。

**受影响工作包：**P05, P06, P17

批准记录：owner / 日期 / 规范版本 / 理由 / 替代方案 / 必增测试。

## 不应称为“冲突”的正常情况

18 Engine 与18 Daily Phases没有一一对应关系本身是正常的，冲突是具体顺序/职责不同。不同Office读取同一数据正常，冲突是两个实体都自称其余额的权威写入者。允许近似价格函数正常，问题是未声明参数、单位、边界、状态依赖，或用无来源buff取代真实数量。

## 全量要求索引的使用边界

`source_units.jsonl`保留8份文档8743个段落/表格行单元，含标题和重复总表；这不是8743项功能，也不是已完成8743项审查。默认implementation_status=UNASSESSED。需从中逐条归并为可验收requirements，再链接实现和测试；禁止因为有索引就把需求标为DONE。

第二ZIP实际为7份：Master+6Office。Constitution来自此前上传，作为第8份交叉约束，不冒充第二ZIP自带文件。

Master固定目录实际计数：12 commodities、12 production sectors、22 technologies、38 project types；E16 A列23个国际活动子类型。Trade AppendixB是不同粒度活动家族，不能以较少条目覆盖Master子类型。
