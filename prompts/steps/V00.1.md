## Authority
Treat `requirements.docx` / Constitution as non-negotiable P0/P1 law. Follow `AGENTS.md`, `PLANS.md`, `planning/r2_steps.json`, relevant Master/Office specifications, approved ADRs, and `docs/governance/FAST_MAINLINE_REVIEW_POLICY.json`.

## Gate
- Work package: V00 — 新仓库边界、资料导入与可运行脚手架
- Stage: S0
- Execution mode: `NORMAL`
- Hard dependencies: none

Before implementation, validate dependency readiness under the central policy. A P0 dependency is ready only after blocking independent review; a lower-risk dependency may use only a policy-valid continuation or verification record.

## Goal
冻结 Node/pnpm/TypeScript/Vite/React/test/lint 版本、真实命令与环境安全边界。

## Exit gate
干净安装、lint/typecheck/test/build 与生产写保护均有真实证据。

## Required workflow
1. Read only the relevant specs/ADRs and inspect current code.
2. Write `docs/exec-plans/V00.1.md` before product code changes.
3. Classify the actual change by its highest affected boundary; uncertainty resolves upward and classification may never be lowered to bypass review.
4. Declare affected authoritative owners, reads/writes/events/commands, DB/RLS/time implications, and legacy impact.
5. Implement only this step and run real unit/integration/invariant/security/governance checks appropriate to scope. Preserve `FAIL` and `NOT_RUN` honestly.
6. Create `docs/reports/V00.1/IMPLEMENTATION.md` and `TEST_EVIDENCE.json`.
7. Apply `docs/governance/FAST_MAINLINE_REVIEW_POLICY.json` to status, review timing, merge, and continuation. P0 always stops for independent review. P1 review may be deferred only to its named Work Package gate. P2/P3 fast-track requires the policy evidence record.
8. Never proceed past an unresolved blocker or a failed mandatory check.
