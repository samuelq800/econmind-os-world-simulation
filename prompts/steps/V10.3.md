## Required workflow
1. Read only the relevant specs/ADRs and inspect current code.
2. Write `docs/exec-plans/V10.3.md` before product code changes.
3. Declare affected authoritative owners, reads/writes/events/commands, DB/RLS/time implications, and legacy impact.
4. Implement only this step. Do not auto-run the next step.
5. Run real unit/integration/invariant/security tests appropriate to this scope. Use `NOT_RUN` honestly.
6. Create `docs/reports/V10.3/IMPLEMENTATION.md` and `TEST_EVIDENCE.json`.
7. Final status must be one of: `IN_PROGRESS`, `IMPLEMENTED_UNVERIFIED`, or `BLOCKED`. Implementation agent may not mark `CHANGES_REQUIRED` or `VERIFIED`.
   - `IMPLEMENTED_UNVERIFIED`: implementation for this step is complete and required local evidence exists, but independent review has not approved it.
   - `IN_PROGRESS`: some work was completed, but the step is not implementation-complete.
   - `BLOCKED`: work cannot safely continue because an external decision, missing prerequisite, environment limitation, or P0/P1 conflict prevents progress.
8. Next action must be independent review, not the next implementation step.
