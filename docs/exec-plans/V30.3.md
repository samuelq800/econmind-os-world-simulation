# V30.3 recovery measurement — non-authoritative preparation

Status: `PREPARATION_ONLY_NOT_V30_3_STARTED`. V30.2 and earlier hard
dependencies are not formally ready; this plan authorizes only a pure
measurement helper and focused tests, not a recovery drill or gate claim.

## Scope and boundary

- Owner: `tools/v30/recovery-measurement-preparation.ts`, focused tests, and
  preparation evidence. No Worker, World Core, API, migration, RLS, backup
  service, runtime configuration, production Supabase, or original website.
- Read: explicitly caller-reported incident, latest committed, recovery-point,
  and service-recovered instants; WorldVersion before/after; immutable code SHA
  and backup identifier.
- Write: none. No database connection, file I/O, restore, command, event,
  receipt, WorldVersion advance, or backup mutation.
- Output: arithmetic RPO/RTO estimates and lost committed version count with
  an unverified status. Malformed/non-UTC/out-of-order evidence fails closed.

## Real exit gate remains open

After V30.2 and its predecessors are formally ready, perform an actual
disposable non-production backup restore, replay/ledger reconciliation and
fencing/idempotency checks. Bind independent machine logs and artifact hashes
to one immutable code/model/DB target; measure real RPO/RTO. This helper alone
cannot prove that a restore occurred or that recovered state is correct.
