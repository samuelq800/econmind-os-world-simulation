## Exact contract

- Hard dependency: V08.2.
- Purpose: establish opening-balance/source provenance plus inventory and
  financial reconciliation tools.
- Acceptance: test seeds contain counterpart financial entries and a snapshot
  never becomes the sole Source of Truth.
- Owners: opening seed records establish the initial facts consumed by the
  V08.1 World Inventory Posting and V08.2 World Financial Posting ledgers. They
  do not create another mutable writer.

The minimum contract is an immutable, versioned opening seed manifest for one
World at opening WorldVersion zero. It binds exact V07 replay versions, a
canonical seed fingerprint, an explicit source registry with type, locator,
source version and byte hash, positive inventory opening entries and balanced
financial opening batches. Every opening fact references one declared source.

## Reconciliation and lineage

Reconstruction starts from the validated opening seed and consumes one globally
ordered V07 `AuthoritativeTransition` sequence. Each transition binds zero or
more Inventory and Financial Postings to the same World, Command/Event evidence
and exact `N -> N+1` WorldVersion boundary. Both projections observe that one
global head, and a joint transition yields no authoritative candidate if either
ledger invariant fails. A supplied snapshot is only untrusted comparison data.
A missing snapshot must not prevent reconstruction; a mismatching snapshot is
reported and never averaged, silently repaired or accepted as truth.

Inventory reconciliation compares the exact canonical V08.1 ledger projection.
Financial reconciliation compares the exact canonical V08.2 account/position
projection and requires debit equals credit per currency for every opening
batch. The implementation uses only `Quantity`, `Money`, canonical strings and
SHA-256 equality; it introduces no tolerances.

## V07/V09 compatibility

The opening manifest binds `CURRENT_REPLAY_BINDING`; later postings retain
their V07 Command/Event/SimTime/WorldVersion evidence and their own idempotency
rules. V08.3 supplies deterministic Core reconstruction and diagnostics only.
V09 still owns the runtime lease, fencing, atomic all-or-zero commit,
persistence transaction and recovery orchestration.

## P0/P1 risks

P0: unbalanced opening finance, negative/zero physical opening stock, missing
source provenance, accepting tampered hashes, nondeterministic seed, snapshot
as truth, silent reconciliation repair, competing writer, V07 version mismatch,
premature V09 mechanics, migration divergence or production mutation.

P1: ambiguous fixture versus dataset source, duplicate account identity,
unclear signed financial convention, incomplete diagnostic detail, or future
domain behavior silently embedded in foundation seed mechanics.
