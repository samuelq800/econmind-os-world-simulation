# V00.1 — Repository Foundation, Toolchain Verification and Version Freeze

## Status

Implementation plan for V00.1 only. This plan does not authorize V00.2 or later
work.

## Governing constraints

- The EconMind Constitution is binding and fail-closed.
- The user-supplied V00.1 execution packet is the active R2 contract.
- Expected `PLANS.md` and additional R2 artifacts were not present at execution
  start; their contents must not be inferred.
- Implementation and independent review are separate stages.

## Objective

Establish a reproducible TypeScript monorepo with explicit application
responsibilities, genuine quality gates, and safeguards against accidental use
of the linked production Supabase project.

## In scope

1. Freeze Node.js, pnpm, TypeScript, Vite, React, Vitest, ESLint, and formatting
   policy to exact versions.
2. Create minimal `world-web`, `world-api`, and `world-worker` applications that
   compile while making clear that authority/simulation is disabled.
3. Reserve the package architecture without creating empty implementation
   theater.
4. Add real install, lint, formatting, typecheck, unit test, boundary test,
   environment check, and build commands.
5. Add import-boundary rules with both positive and negative tests.
6. Document and enforce environment safety around the linked Supabase target.
7. Record implementation notes and machine-readable test evidence.

## Explicitly out of scope

- World State, economic engines, command/event implementation, database schema,
  migrations, RLS, and settlement flows;
- MapLibre, deck.gl, PMTiles, Web Workers, Comlink, DuckDB, Arrow, Parquet, Rust,
  and WebAssembly;
- deployment, production mutation, V00.2+, and independent review;
- `docs/reports/V00.1/REVIEW_FINAL.md`.

## Toolchain decision

- Node.js 24.20.0 LTS
- pnpm 12.3.4
- TypeScript 6.0.3
- Vite 8.2.2
- React and React DOM 19.2.8
- Vitest 5.0.0
- ESLint 10.10.0 with typescript-eslint 8.70.0
- Prettier 3.9.6

Versions are exact in manifests. `.nvmrc`, `.node-version`, package engines, the
pnpm package-manager declaration, and a fail-closed preinstall check prevent
silent toolchain drift.

## Validation plan

Run every command using Node 24.20.0 and pnpm 12.3.4:

1. `pnpm install --frozen-lockfile`
2. `pnpm lint`
3. `pnpm format:check`
4. `pnpm typecheck`
5. `pnpm test`
6. `pnpm test:boundaries`
7. `pnpm env:check`
8. `pnpm secrets:check`
9. `pnpm build`
10. `pnpm check`
11. exercise the Supabase command guard with allowed and blocked arguments;
12. inspect the working tree and scan tracked candidates for credential patterns.

Failures must be fixed inside V00.1 or recorded honestly. Passing implementation
checks produce `IMPLEMENTED_UNVERIFIED`, never `VERIFIED`; independent review is
still required.
