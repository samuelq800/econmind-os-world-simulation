## Authority and candidate contract

`planning/r2_steps.json` and `prompts/steps/V24.2.md` require a shock cause
layer, crisis start/end, legal pause/resume and approvals. Constitution R100
and Master Shock/Admin rules forbid direct GDP, inflation, stability or score
edits: Admin may propose controlled cause changes for existing engine-owned
fields through Event Kernel. Approved ADR-03 requires integer simulation
milliseconds and no SimTime catch-up for paused wall time. This module does
not itself execute Event Kernel work, authorize a command, change clock, or
write an authoritative state.

- Accept immutable same-snapshot crisis-state, action, authorization and
  cause facts. State/action versions, world/season/actor, integer tick and
  action uniqueness witness must match. A caller-owned authorization fact
  must attest a server decision and list explicit version-bound approval
  requirements; Core checks every required approval exactly once. It cannot
  authenticate the server or determine the future approval resolver.
- `START_CRISIS` requires inactive crisis, RUNNING clock and at least one
  cause; `END_CRISIS` requires active crisis and no new cause. `PAUSE_WORLD`
  requires RUNNING clock; `RESUME_WORLD` requires PAUSED clock. Pause/resume
  propose the same frozen SimTime, never accumulated paused wall time.
- Each start cause targets a fixed, non-macro bottom-layer field and has a
  distinct source fact/receipt, target owner/object, explicit before/delta/
  calculated after, with exact money or quantity unit. Losses cannot exceed
  stock/capacity; demand surges cannot be negative. Population displacement
  needs an explicit scenario reference. Return candidate event proposals and
  causal transitions; no economic posting or materialization occurs.
- Bind contract-like action/authority/cause fact lineage, snapshot hash,
  source version and canonical replay preimage. Replay must rerun from the
  same facts and compare full results, not trust an editable hash alone.
