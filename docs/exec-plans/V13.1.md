# V13.1 — E09 Energy Foundation-Mode Candidate

## Status and boundary

`FOUNDATION_IMPLEMENTED_UNVERIFIED`. This is a pure `packages/core` candidate,
not the start of V13.1. It creates no Command, Event, worker path, database
state, migration, RLS policy, API route, UI behaviour, product transition, or
production effect.

## Scope

- Read immutable, exact `MW` capacity, `MWh` energy, fuel, grid-flow, and
  caller-prioritised allocation facts through source/predecessor/version/
  snapshot/time/payload bindings.
- Read V12 usable-fuel availability by explicit read-only availability and
  inventory references only; emit an inert proposed before/delta/after fuel
  transition rather than mutate E08 state.
- Cap generated `MWh` by available fuel before allocating grid energy. Allocate
  only caller-ordered demands and expose physical shortage for every unmet MWh.
- Emit deterministic canonical replay evidence with no price, dispatch-policy,
  default, or rounding formula.

## Acceptance target

`MW` and `MWh` cannot be interchanged. Fuel shortage must reduce generated and
allocated `MWh`; a downstream consumer receives its exact delivered amount and
shortage, not an unconstrained availability claim.

## Dependencies retained

V13.1 retains V03.3, V11.3, and V12.3 as normal-mode hard dependencies. This
candidate does not satisfy, bypass, or reclassify them.
