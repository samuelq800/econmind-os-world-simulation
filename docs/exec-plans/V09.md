## Single-writer and atomicity architecture

The Worker is the sole economic writer. A per-World renewable lease and
monotonically increasing fencing token reject an expired, superseded or stale
holder at commit time. WorldVersion independently rejects a valid holder working
from stale state.

One short authoritative database transaction locks the World head and rechecks
lease/fence, WorldVersion, durable idempotency and current ADR-20 authorization.
It then validates the deterministic candidate and V08 invariants; persists
Inventory Posting(s), Financial Posting(s), Event(s), complete final receipt,
WorldVersion, outbox facts and current materializations; and commits all or none.

Candidate state is private and disposable. Outbox delivery and projections may
run asynchronously after commit, but neither can replay the economic transition.

## V07/V08 ownership boundaries

- V07 continues to own Command identity/queue semantics, idempotency, Event,
  receipt, outbox/consumer receipt and replay lineage.
- V08 continues to own Inventory Posting, Financial Posting,
  opening/reconciliation semantics, exact arithmetic and conservation.
- V09 owns exclusive-writer enforcement and coordinates those existing facts in
  a single fenced, versioned, recovery-safe commit. It creates no competing
  Command, Event or Ledger semantics.

## Expected schema and migration ownership

V09 is expected to propose forward-only candidates in the sole V02 migration
chain for:

- per-World lease holder, expiry and monotonic fencing state;
- transaction-time fence/WorldVersion enforcement;
- V08 Inventory/Financial Posting and opening/reconciliation persistence if not
  already present on authoritative main at entry;
- constraints and a guarded transaction path joining V07 Command/Event/receipt/
  outbox facts to V08 Postings and WorldVersion.

Exact migration numbers, object names and database API shapes are not frozen by
this plan. Candidates remain branch-local and unpromoted until immutable schema
evidence passes clean/existing rehearsals, RLS/grant checks and independent
review. Production publication requires separate human authorization. V09.3
adds schema only for a proven recovery invariant gap.

## P0/P1 test architecture

P0 evidence uses real PostgreSQL and process/connection separation to cover two
writers, expired/stale holders, stale fences, duplicate retry, partial
transaction attempts, Event/Posting asymmetry, inconsistent receipt,
WorldVersion mismatch, pre-commit crash, post-commit/pre-ack crash, outbox retry,
recovery replay, commit-time stale authorization and deterministic restart.

P1 evidence covers bounded serialization/deadlock retry, lease-renewal edges,
repeated takeover, checkpoint/watermark reconciliation, projection rebuild,
large Event sets/replay windows, observability and multi-World isolation. This is
a bounded engineering failure matrix, not an open-ended attack campaign.

## Package exit gate

Package exit requires every package acceptance criterion:

- stale writer cannot commit;
- pre-commit crash produces no half economy;
- post-commit retry produces no duplicate economy;
- downstream notification failure is redeliverable;
- daily-close and player-command boundaries have deterministic order.

It also requires immutable independent package approval, owner acceptance and
authorized promotion/merge. No V09 scoped-continuation record currently exists;
therefore default P0 review blocking applies between dependent steps unless an
exact future owner policy validly changes that gate.
