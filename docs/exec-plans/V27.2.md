and inventory conservation and deterministic calibration evidence. Automated

## Pure validation contract

- Add only a new `packages/core/src/calibration` module and focused
  `tests/world-core` coverage. Do not edit `packages/core/src/opening`, which is
  owned by a parallel slice.
- Accept inert, explicit candidate input only. Every numeric input must carry
  a canonical decimal, destination unit, source unit, source reference and an
  explicit nullable assumption reference. Sources must declare classification,
  locator, version and content hash.
- Require exactly 70 unique countries before returning `INPUT_CLOSED`. Missing
  countries, empty required domains or placeholder evidence return an explicit
  `INCOMPLETE` result; they are never synthesized.
- Reject unknown fields, duplicate identities, foreign source references,
  source/destination unit changes, and any `index_0_100` value used as a real
  physical, person, ratio or monetary input. This preparation does not invent
  a conversion method.
- Validate exact debit/credit equality for each opening financial batch,
  physical inventory bucket equality, geological layer equality, installed /
  operational facility bounds, staffing bounds and supplier-share closure.
- Require all derived or synthetic quantities to carry a non-empty exact
  before/delta/after change chain with source and assumption references. The
  chain must close exactly and end at the declared value. Observed direct
  values may not silently carry a transformation.
- Archetype identifiers may be descriptive provenance only. Reject per-tick,
  per-turn, persistent multiplier or buff fields through exact runtime shapes;
  emit no runtime modifier or economic state mutation.
- Canonicalize country/source/domain order and bind the validated candidate to
  an injected SHA-256 implementation for deterministic replay comparison.
