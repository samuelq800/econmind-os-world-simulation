# V11.3 — E02–E03 population/labour cross-engine invariant execution plan

**Status:** `OWNER_AUTHORIZED_IMPLEMENTATION_UNVERIFIED`
**Baseline:** `47526ea2219ece011da82e397cf5435b1d044ea8`
**Authority:** `docs/governance/WORLD_CORE_V11_3_CONDITIONAL_CONTINUATION_POLICY.json`

## Boundary and classification

V11.3 is a P0 cross-engine authoritative-state validation change. Its scope is
one pure validator in `packages/core/src/labour/`, the core export, one focused
test suite, and V11.3 plan/evidence documents. It is a non-production candidate
only; it cannot become `VERIFIED`, merge to main, deploy, use shared Supabase,
publish a migration, or create V12+ work.

E02 remains the sole owner of population and E03 remains the sole owner of
labour/skills/jobs/wages. V11.3 creates neither a population nor labour source
of truth. It reads the existing E02/E03 states and evidence, validates them,
and returns no authoritative replacement state.

## Contract

The validator accepts caller-selected source and result snapshots. Each snapshot
contains E02 state plus label, and E03 state plus population availability and
label. A label has an opaque caller-supplied snapshot ID, day index and time
label. V11.3 only requires E02/E03 labels to be exactly equal for a given
snapshot and requires all transition evidence to carry the result day index. It
does not interpret or choose opening/current/prior/phase ordering.

For a submitted source/result pair, V11.3 must:

- validate both source states through the existing E02/E03 pure cores;
- replay supplied canonical E02 facts from the source and require the exact
  result E02 state and action evidence;
- replay supplied canonical E03 facts from the source and require the exact
  result E03 state and action evidence;
- require every E03 location availability to be non-negative and that the sum
  for each country does not exceed E02 result `workingAge16To64`;
- prove skill/labour changes arise only from E03's explicit education transition
  or migration-labour-entry facts, rather than direct state edits;
- require every E03 migration labour entry to link by handoff ID to an explicit
  E02 migration-arrival evidence record and ensure total linked labour entries
  do not exceed that arrival's count; and
- rely on the revalidated E03 state to prove aggregate employed equals combined
  private/public position employment, preventing dual occupation.

## ADR cut line

ADR-04 and ADR-08 remain `PROPOSED_NOT_APPROVED`. V11.3 may compare explicit
caller labels but cannot infer their semantics or choose an ordering. It adds
no population, participation, matching, wage, price, rate, money or rounding
formula/default. Missing or incompatible labels, source evidence, replay state,
or exact links fail closed.

## Expected files and evidence

1. `packages/core/src/labour/population-labour-invariants.ts` with a pure
   validator only; no persistence/command/event/receipt/API/worker boundary.
2. Core export and `tests/world-core/v11-3-population-labour-invariants.test.ts`.
3. Tests for valid explicit E02→E03 migration/education evidence, snapshot-label
   mismatch, direct labour mutation, availability overage, unlinked or overused
   migration handoff, public/private employment mismatch, malformed evidence,
   and deterministic evidence ordering.
4. Focused test, core typecheck/build, scoped lint/format, authoritative,
   boundary, foundation-policy, environment and secret checks. Retain `NOT_RUN`
   honestly for excluded database/full-repository work.
5. V11.3 implementation and test-evidence reports bound to the immutable
   candidate. Independent V11.3 review remains required before `VERIFIED` or
   promotion.

## Stop conditions

Stop for a P0/MAJOR finding, failed invariant, requirement to select timing or
derive a formula, or any database/RLS/migration/API/worker/UI/production/V12+
requirement. Do not modify E02 or E03 runtime modules to make an invalid link
pass; the validator must reject it.
