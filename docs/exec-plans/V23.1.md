## Planned calculation boundary

- New `packages/core` module accepts immutable same-snapshot caller facts
  only. It never reads/writes database, world state, Command, Event, receipt,
  posting, materialization, API, UI or production Supabase.
- Inputs declare one country, period start/end, currency and calculation
  version. Each sector gross output and intermediate consumption, and each
  product-tax/subsidy amount, carries a distinct source receipt reference.
  Fact provenance binds source, predecessors, snapshot/version/hash and
  simulation time. No missing component is silently treated as zero.
- Compute per-sector value added exactly as gross output minus intermediate
  consumption, then production GDP as the sum of those values plus product
  taxes minus product subsidies. Construction approval, payment, transfer or
  commissioning alone is not a production source; only caller-attested
  settled real production is eligible. Duplicate receipts within the same
  contribution role are rejected; one real transaction may legitimately
  support production and expenditure, or supplier output and buyer input.
- A separately supplied, fully populated C/I/G/X/M fact may be compared to
  production GDP. C/I/G/X/M are never an alternate authoritative GDP output.
  Mismatch raises an explicit reconciliation error carrying both values and
  their exact signed difference. Missing categories, period/version/currency
  mismatch and pre-delivery X/M are rejected.
- Return deterministic exact-decimal results, per-component causal refs and
  canonical replay preimage. Future V09/V23 authoritative owners must verify
  receipt authenticity, completeness, uniqueness across committed periods and
  atomic publication. This preparation cannot assert those properties.
