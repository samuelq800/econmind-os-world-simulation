## Reads, writes and ownership

- Reads immutable opening-seed/checkpoint provenance, exact version binding,
  the append-only authoritative Event sequence, canonical Event payloads and
  hashes, and V06 SimTime already recorded on each Event.
- Produces a pure reconstructed canonical state and replay evidence hash. It
  does not mutate authoritative Events, receipts, World head, queue, outbox,
  snapshot or economic tables.
- `packages/core` owns the pure replay contract, deterministic reducer registry,
  version checks, contiguous sequence validation, canonical state hashing and
  explicit seeded-RNG interface.
- The Worker will eventually invoke replay and compare it with a committed
  head/checkpoint. V07.3 does not add a second writer or a replay write-back
  route.
- V09 owns lease/fencing, private checkpoint persistence, recovery scanning and
  authoritative all-or-zero commit. A replay result is evidence/candidate
  state, never commit authority.

## Replay lineage

- Opening seed plus append-only authoritative Events define lineage. A
  checkpoint may accelerate replay only when it binds World ID, last Event
  sequence, WorldVersion, opening-seed hash, exact version-binding hash,
  canonical state bytes and state hash.
- Replay begins from an immutable canonical opening state or a validated
  checkpoint and consumes only the next contiguous Event sequence for the same
  World.
- Missing, duplicate, reordered, tampered or foreign-World Events fail closed at
  the first offending item. There is no best-effort skip, implicit repair,
  tolerance or use of database row order.
- Historical correction remains a new Event consumed by its registered
  reducer. Replay never UPDATEs/DELETEs/replaces an older Event.

## Version binding

- A replay binding explicitly names replay schema, Event schema, reducer
  registry, engine, model, domain registry and numeric-policy versions.
- The trusted reducer registry declares the exact binding it implements.
  Unknown/mismatched versions stop before the first reducer executes.
- Old Events are replayed only by the compatible registered binding. A new
  runtime version cannot silently reinterpret them.
- Version evolution requires an explicit new binding/reducer path and forward
  migration/correction; no fallback to “latest” is allowed.

## Seeded RNG contract

- The seed is canonical inert data with a cryptographic provenance hash.
- Random values derive only from `(seed, streamId, canonical counter)` through
  the supplied SHA-256 adapter. No `Math.random`, wall time, object iteration or
  process-local state participates.
- Reducers receive an explicit event-scoped deterministic RNG interface. V07.3
  defines reproducibility only and introduces no stochastic economic rule or
  distribution.

## Canonical equality and hash comparison

- Opening/checkpoint state and every reducer output must pass the existing
  inert canonical serializer. Accessors, methods/providers, Proxy behavior,
  hidden/symbol state, unsupported containers and JS-number exact values remain
  rejected.
- Exact equality means identical canonical bytes/hash under the same inputs and
  binding. There is no floating tolerance or noncanonical object equality.
- A live-state comparison returns a deterministic match result or explicit hash
  mismatch; it never overwrites either side.

## Test matrix

| Case                                                         | Required result                                                         |
| ------------------------------------------------------------ | ----------------------------------------------------------------------- |
| Same opening state + Events + seed + versions                | Byte-identical canonical state and state hash on every replay           |
| Object key-order reconstruction                              | Same opening/checkpoint and final hashes                                |
| Missing/gapped Event                                         | Explicit contiguous-sequence failure; no later reducer runs             |
| Duplicate/reordered Event                                    | Explicit failure at first offending sequence                            |
| Other World Event                                            | Explicit failure before state change                                    |
| Tampered payload/fingerprint                                 | Integrity failure; no best-effort replay                                |
| Unknown Event type/reducer                                   | Explicit version/registry failure                                       |
| Event/reducer/engine/model/registry/numeric version mismatch | Block before reducer execution                                          |
| Corrupt checkpoint state/hash/seed/binding                   | Reject checkpoint before continuation                                   |
| Same seed/stream/counter                                     | Same RNG material across reconstruction/restart                         |
| Different seed/stream/counter                                | Domain-separated RNG material                                           |
| Ambient time or trace timestamp change                       | No state/hash effect when authoritative Event fingerprint remains valid |
| Live versus replayed state                                   | Exact hash match or explicit mismatch; no write-back                    |
| V06 SimTime values                                           | Consumed as recorded canonical ticks; no second clock/order rule        |

Property tests use the fixed repository run count and recorded seed/path.

## P0 risks

- Replay silently skips or reorders immutable history, accepts tampered content,
  or creates a second Source of Truth.
- Runtime/model/registry drift reinterprets old Events without an explicit
  compatible binding.
- RNG depends on wall time, global mutable state, platform iteration order or
  an unrecorded seed.
- Checkpoint corruption or stale lineage is accepted as authoritative state.
- Replay reauthorizes committed facts, mutates receipts/Events, or pulls V09
  recovery/commit mechanics forward.

## P1 risks

- Registry/reducer interfaces overfit future Engine implementations.
- Large-state canonicalization is inefficient before V30 profiling.
- Error diagnostics omit the offending sequence/version while remaining
  semantically fail-closed.
