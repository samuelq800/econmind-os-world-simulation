# V00.2 Three Application Runtime Entries and Lifecycle Skeleton

## Status and objective

V00.2 is `IN_PROGRESS`. It will make `world-web`, `world-api`, and
`world-worker` independently runnable real processes with health, readiness,
fail-closed startup, and graceful shutdown behavior. It will also prove that
the three processes can run concurrently. It will not implement V00.3
cross-application health communication or a new unified development command.

## Hard dependencies

- V00.1 is `VERIFIED` at implementation commit
  `c41ddd8fa7c4098e84efdbe8f1839e8690993627`.
- R2 governance is `VERIFIED`, merged into `main`, and post-merge reconciliation
  passed.

## Expected files

- Root/app package scripts for independent runtime startup.
- `apps/world-web/vite.config.ts` for operational health/readiness middleware,
  strict port behavior, and runtime configuration validation.
- `apps/world-api/src/runtime.ts` and `main.ts` for an HTTP process boundary.
- `apps/world-worker/src/runtime.ts` and `main.ts` for a private operational
  health process around the disabled simulation host.
- Focused unit/process integration tests under `tests/foundation/`.
- `status/progress.json`, V00.2 reports, and this execution plan.

## Authority and Source of Truth

No economic or business Source of Truth is introduced or read. The API remains
the future command/query boundary, the worker remains the future authoritative
execution host with simulation disabled, and the web process remains
non-authoritative. Process-local readiness flags are ephemeral operational
state, not World State, a projection, or a durable business record.

## Read write and event paths

- **Reads:** explicit process environment values for `ECONMIND_ENV`, host, and
  port; HTTP liveness/readiness requests; OS process signals.
- **Writes:** health/readiness HTTP responses and redacted lifecycle logs to
  stdout/stderr only.
- **Events:** `SIGINT` and `SIGTERM` are operational shutdown signals. No domain
  event, command, outbox record, or settlement event is created or consumed.
- **Database/RLS/time:** no database connection, table, migration, RLS policy,
  simulation clock, wall-clock economic rule, or persistence path is involved.
- **Supabase:** no SDK import, credential read, network access, CLI mutation, or
  deployment. The linked production integration target remains protected.

## Security boundaries

- Unsupported `ECONMIND_ENV`, malformed/privileged/out-of-range ports, invalid
  hosts, and occupied ports must reject startup with a nonzero exit.
- Web runtime configuration continues to enforce the Vite public-variable
  allowlist before serving.
- Health responses expose only service/lifecycle markers and never secrets,
  hidden state, identities, or economic data.
- The worker health listener defaults to loopback and does not execute
  simulation or authoritative mutation.
- Shutdown stops readiness before closing listeners and completes within a
  bounded grace period.

## Tests

- Unit tests for environment, host, and port validation.
- Real HTTP tests for API and worker health/readiness and unsupported routes.
- Real child-process tests for independent startup and `SIGTERM`/`SIGINT`
  shutdown.
- A concurrent three-process smoke test using isolated loopback ports.
- Negative process tests for invalid environment, invalid port, and occupied
  port startup.
- Repository lint, format, typecheck, application tests, boundary checks,
  environment checks, secret scan, builds, aggregate check, governance
  validation, and `git diff --check`.

## Acceptance gate

All three processes start independently and concurrently; health/readiness
respond through real entry points; invalid environment/port conditions fail
closed; both termination signals shut down cleanly; no database or Supabase
access/mutation occurs. Evidence must record `PASS`, `FAIL`, `NOT_RUN`, or
`INSUFFICIENT_EVIDENCE` honestly.

## Excluded future work

V00.3 Web-to-API health communication, worker-to-API/bootstrap integration, a
unified development command, business routes, authentication, domain commands,
World State, events, persistence, RLS, migrations, Realtime, deployment, and
all V01+ work are excluded.
