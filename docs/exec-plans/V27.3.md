# V27.3 — 无人国家 NPC Controller: isolated preparation

## Gate and classification

V27.2 is PLANNED and ADR-13 is PROPOSED_NOT_APPROVED at this branch base. This is a P0-sensitive Core authorization/economic boundary, so this branch is `PREPARATION_ONLY`, not V27.3 execution, verification, or promotion. No status/ADR register changes, production access, migration, or integration with an authoritative host.

## Narrow slice

Add a pure, unexported-from-package-index `packages/core/src/npc` preparer for one deterministic resource-allocation **candidate**. It consumes a versioned model choice, one real `AuthorizedOfficeContext`, one approved `ApprovalProposal` matching the candidate fingerprint, and version-aligned funding and `AVAILABLE` inventory facts. Missing or conflicting inputs produce `UNAVAILABLE`. Exact `Money`/`Quantity` arithmetic prevents over-budget or over-stock candidates. Output is only a replayable preimage and proposed payload; it is not a `CanonicalCommand`, an accepted order, an Event, a Posting, or an authorization token. Final submission must independently reauthorize and recheck approval, funds, inventory, and WorldVersion in the existing Command/atomic writer path.

This slice does not define the future NPC identity/principal or policy in ADR-13. A caller must supply authorization already issued by existing Core authorization; no synthetic NPC principal, implicit approval, hidden resources, random policy, or automatic offer acceptance is created. Until ADR-13 and V27.2 close, the module cannot be wired into a runtime.

## Ownership and effects

- Owner: `packages/core/src/npc` and focused `tests/world-core` only, plus this plan and evidence report.
- Reads: caller-supplied World/country/version/SimTime, model ID/version, office context, approval, financial and inventory facts. No direct store reads.
- Writes/commands/events: none. The candidate describes a potential future resource allocation only.
- DB/RLS/time: no schema/migration/RLS change; no clock read; caller-provided SimTime is replayed.
- Legacy: no main-site or existing runtime changes.

## Verification

Focused tests cover deterministic replay and exact arithmetic; missing model/authority/approval/facts; wrong World/country/version/capability; rejected, stale, or mismatched approval; insufficient cash/budget/stock; wrong currency/unit; non-AVAILABLE stock; no executable Command/Posting/Event output. Run Core build/typecheck, focused tests, formatting/lint and boundary checks. Report any missing integration checks as `NOT_RUN`; independent P0 review remains required before use.
