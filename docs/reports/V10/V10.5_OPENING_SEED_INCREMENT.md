lineage boundary**. It does not implement the delivery preparation source,
connect a worker to Supabase, execute DDL outside disposable local rehearsal,
or grant a browser any authority.

- Core now rehydrates an opening seed only through its canonical constructors.
  It recomputes source-payload hashes, account/amount validation, replay
  binding, and the final seed fingerprint before treating the deserialized
  record as valid.

  `world_v2.opening_seed` store. Creation is permitted only while the durable
  World head remains `(WorldVersion=0, EventSequence=0)`; rows are thereafter
  append-only, RLS-protected, and explicitly unavailable to browser roles.
- `WorldOpeningSeedStore` supports an explicit, idempotent server bootstrap and
  canonical read-back. It rejects `TEST_FIXTURE` provenance before a row can be
  written and revalidates the retrieved seed before it can feed replay.
