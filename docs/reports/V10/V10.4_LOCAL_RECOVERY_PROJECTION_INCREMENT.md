## Implemented local candidate

This increment adds only derived/operational delivery work around the already
committed narrow Treasury-GCU delivery facts. It adds no economic rule, browser
authority, user authorization path, server connection, or database migration.

- `NarrowTreasuryGcuDeliveryProjectionRebuilder` derives the one current delivery
  materialization from the committed delivery Event plus its exact inventory and
  financial Posting fingerprints. It rejects malformed or non-canonical durable
  data, accepts no caller-provided balance, and writes no authoritative fact.
- The atomic delivery draft now writes that current materialization in the same
  transaction as its Event, Postings, receipt, outbox, queue finalization, and
  World-head advance.
- `NarrowTreasuryGcuDeliveryOutboxConsumer` sends only the committed outbox
  payload. It provides the durable Event ID as the sink idempotency key; a sink
  failure stays `PENDING`, and an already-delivered receipt short-circuits a
  later dispatch without recreating any economic transition.
