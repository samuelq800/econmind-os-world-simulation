# V10.1 Query-Boundary Increment

## Scope completed in this increment

This increment turns the prepared V10 read boundary into an HTTP-neutral,
server-owned query handler. It accepts a raw authorization header and request,
requires cryptographic JWT verification before the entitlement query, and
returns the versioned World-read response envelope. The handler receives its
PostgreSQL executor and verifier from the server runtime; it does not create a
connection, read browser identity, or install a network route.

The existing read adapter now includes `NEGOTIATION_PARTY` alongside `COUNTRY`
and `OFFICE_PRIVATE`. The two-country test fixture remains explicitly
`TEST_ONLY_NON_AUTHORITATIVE`; it is used only to exercise the authenticated
Country read path and cannot become World State or Office authority.

The generic worker publication boundary is lease-guarded and now owns only
`NEGOTIATION_PARTY`; it obtains the current WorldVersion and event sequence
through the database writer guard in the same transaction, binds each row to
that watermark, and preserves `PUBLIC` and `ADMIN` for their future owners.
Country and Office-private data deliberately cannot enter that generic
boundary.

The Worker now also rebuilds `COUNTRY` and `OFFICE_PRIVATE` read entitlements
from active rows in the existing server-owned
`world_v2.current_commit_authorization` projection. It runs under the same
writer-lease/WorldVersion guard, deduplicates only consistent authorization
revisions, atomically replaces those two classifications, and preserves
`NEGOTIATION_PARTY` and `ADMIN` rows for their future authoritative sources.
Office-private scope keys are injectively derived by server code from the
country/Office pair; browser claims and test fixtures are not an input.

The Worker now also derives compact Country and Office-private activity
payloads directly from append-only `authoritative_event` rows joined to their
canonical `command_submission` facts. The payloads contain only labelled event
counts and last-event watermarks for the matching country/Office; they do not
infer balances, prices, inventory quantities, or other economic values from
counts. This publisher is the sole Country/Office projection writer and shares
the lease/WorldVersion guard and full replacement watermark checks.

The Worker now also has a named-party materializer that reads only
`world_v2.current_negotiation_party_membership`, an initially empty,
server-owned current-membership source introduced by candidate migration 0014.
It atomically replaces the `NEGOTIATION_PARTY` entitlement and projection rows
under the writer guard. A party payload lists only the active member countries
and Offices; it does not disclose `AuthSubject` values or authorization
versions. The source intentionally contains no school field, school lookup, or
school-isolation rule, so a future authorized server workflow may create
cross-school and cross-country groups. With no active rows, it removes stale
party access and leaves the query boundary fail-closed.

## Preserved limitations and next V10.1 work

- The default API runtime still has no public World-read route or live JWT/
  PostgreSQL dependency injection.
- The branch has not run actual PostgreSQL, non-production Supabase RLS/grant,
  deployment, migration-publication, or production/shared-Supabase evidence.
- The source remains empty until a separately authorized server workflow
  creates and maintains current party membership. The local test inserts its
  rows only into disposable PGlite; it is not a runtime writer, fixture or
  operational membership record.
- The named-party source-to-query test verifies an injected local JWT verifier,
  local PGlite executor and two direct test memberships only. It proves neither
  a live route/verifier nor an external database, RLS/grant, deployment or
  production/shared-Supabase environment.
- Exact ledger-derived economic summaries remain V10.1 work. This increment
  neither claims a runtime fixture nor promotes a projection to an authority
  source.

Accordingly, V10.1 remains `IN_PROGRESS`, and this increment is
`IMPLEMENTED_UNVERIFIED` pending the remaining scoped implementation and an
independent review of its immutable candidate.
