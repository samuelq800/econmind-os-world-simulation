## Concrete missing source and constructor dependencies

`CaptainPoliticalCapitalRuntimeReader.read` currently receives world/country, command ID/fingerprint, expected World version, SimTime, reason reference and explicit observation time. Its output is either exact `MISSING` gaps or `READ` with `CaptainPoliticalCapitalSourceSnapshot` and a real writer lease. There is no concrete Captain implementation in the inspected Worker tree.

The source snapshot requires all of: world/country/head/event sequence, exact `FoundationTraceRequest`, `capitalFact<PoliticalCapitalSnapshot>` and actual country `reasonFact<{countryRef,recordRef,reason}>`. Hashes and `FoundationFact` constructors validate syntax and consistency; the Core source explicitly states they are not an authority issuer. `reasonFactRef` is only a lookup key, not the actual cabinet record or proof that the record is current and lawfully issued.

The inspected migration/proposal SQL has no Captain-specific political-capital genesis/operating register or reason-record issuer/admission contract. `OpeningSeed` has generic source documents plus inventory/financial entries; `RebuiltV08Ledgers` reconstructs inventory/financial state, not a political-capital domain genesis. A generic source document cannot acquire Captain semantics or admission merely because a new adapter parses it.

`apps/world-worker/src/persistence/validated-canonical-lineage.ts` can provide a callback-scoped, same-executor view of the actual canonical seed/head/transitions through `DurableV08LedgerLineageReader`. It explicitly proves data validation and lifetime only, not admission or commit authority. Core `replayCaptainPoliticalCapitalAllocation` requires an already known domain predecessor. Taking the first allocation event's embedded source snapshot as genesis would make the event assert its own authority and is not an acceptable bootstrap.

There is also no ready Captain currentness guard to borrow. `createAtomicCommandLifecyclePersistence` calculates the candidate before its short commit transaction. `AtomicTransitionRepository.#assertPlanSourceCurrent` and `GoverningSourceReadBindingV1` in `projections/governing-source-commit-boundary-contract.ts` are strictly Social PLAN contracts. Captain composition does not supply that port. A new reader's completed read transaction, matching hash, mutable snapshot or lexical lineage token cannot preserve revocation/current-source protection until another transaction commits.

These are source authority and atomic integration decisions, not a missing DTO conversion. Creating `captain-runtime-snapshot-reader.ts` now would either require caller-supplied trusted snapshots/callbacks or invent a source registry and protection semantics. Neither is implemented here.

## Minimum source contract for the next bounded implementation

The following is a proposed design checklist, not an executable issuer or approved API. Reuse the current canonical command, political-capital payload, event, global head, lease and atomic repository. Do not add an alternate balance authority or another dispatcher.

| Required dependency       | Minimum authoritative content and validation                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admitted Captain genesis  | Actual world/country, bound opening seed ID/fingerprint and replay/model revision, accepted political-capital semantic revision, exact initial `PoliticalCapitalSnapshot`, immutable original references/bytes, responsible issuer/custodian and actual owner adoption/admission evidence. Existing fixture quantities are not defaults.                                                                            |
| Political-capital history | Complete committed prefix to the actual head, canonical submissions/events/final receipts, country scope and event taxonomy. Reuse validated canonical lineage and existing Captain replay. Every event that can generate/spend/reallocate capital must have defined accepted meaning; unknown effects or a gap fail closed. Unrelated events must still advance the shared cursor under an explicit reviewed rule. |
| Actual reason record      | Lookup the requested `reasonFactRef` in a real immutable country record, with original issuer/source reference, revision, canonical bytes/hash, effective interval, predecessor/supersession/revocation and admission binding. Require nonblank reason, exact country and lawful original record reference. Never synthesize contents from the request or UI.                                                       |
| Consistent read cutoff    | Read actual global head, complete admitted domain lineage, actual reason revision and current writer lease under one defined consistent cutoff. Return the existing source DTO only after this validation. Construction must use real server dependencies; HTTP/request DTOs cannot supply source results.                                                                                                          |
| Commit currentness        | Define Captain-specific source read binding and mandatory commit recheck against the actual transaction/head, including original revision/admission/revocation guards held through COMMIT. Preserve existing source/lease/head lock order and existing CAS/fence/authorization. Do not relabel the Social-only guard. Immutable/nonrevocable source assumptions need explicit reviewed evidence.                    |
| Membership and lease      | Reuse real current `CAPTAIN_CABINET` command-bound commit authorization and writer-lease owner/fence/validity. Source issuer/admission and user capability remain distinct checks; an actual seat cannot legalize a fabricated genesis.                                                                                                                                                                             |

The minimal safe construction needs an actual database/lineage reader, separately reviewed admitted Captain-source custodian, real reason-record resolver, current lease reader and cooperating Captain commit-source protection. A proposed `withSnapshotFrom(executor, request, consume)` custody lifetime can describe read association, but a callback shape alone does not establish locks or authority. Add concrete implementation only after its source store, admission policy, native guard semantics and transaction wiring are specified and reviewable.

Missing inputs continue to return the existing exact missing categories. Malformed, mismatched, revoked or contradictory sources must reject; they must not be reclassified as harmless absence. A future positive fixture must remain explicitly TEST_ONLY and cannot register itself in production.
