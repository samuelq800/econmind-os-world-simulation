## 修复效果与剩余问题

短混合阶段只有读池借用，没有 Worker 规划事务；读池等待 P95 约 **0.099ms**，事件循环延迟 P95 约 **10.85ms**。显式创建规划仍可获得真实选项。

前一轮未修复基线的短混合中 CB P95 为 4951.69ms、Social P95 为 7736.41ms、读池等待 P95 为 4628.50ms。两轮使用相同数据规模、资源限额、正式池上限和约 20 次/秒输入，但本轮短对照交替使用两个身份/国家，前轮只有一个；不能将跨轮数值当作严格逐项相同的实验。本轮自己的两段短对照具有相同身份分布。

持续混合阶段重新出现明显排队：

- 1270 次 HTTP 读取对应读池 1781 次借用；等待平均约 1431ms、P95 **3272ms**，持有平均约 61ms、P95 129ms。这个比例与额外尝试相符，需要进一步按请求/SQL 分解，不能仅凭计数唯一归因。
- Worker 连接等待 P95 约 0.085ms；事件循环延迟 P95 **11.39ms**。本次不是前轮短场景中同样幅度的同步事件循环阻塞。
- 混合阶段 8 条命令的 HTTP ACK 从约 0.49 秒逐渐升至约 3.39 秒，包含派生发布的完成耗时约 4.49–13.49 秒。持久 FINAL 先于派生完成，全部 9 条非初始化命令的持久 FINAL P95 为 4559ms；不能把两者混称为同一个延迟。
- 本轮读池没有记录 CONNECT 异常，Node 日志也没有数据库连接/查询超时诊断。约十秒的 HTTP 失败与整体请求预算耗尽相符，不能直接写成“连接池单次 connect 超时已复现”，也没有本轮 SQL profile 来确定唯一慢查询。
- 启动日志另有两条 `CB_OMO_INDEPENDENT_SOURCE_ADOPTION_REQUIRED`，属于未装载独立 OMO 采用来源时的拒绝。预算及所测读取没有因此失败，本轮也不宣称 OMO 执行通过。

下一步只围绕持续发布窗口跟踪当前 seat/header、当前页读取和有界重试各自的耗时/次数，确认重复工作后做最小修复；保持现有授权、撤销、来源、head 和财政边界。暂不增加服务、缓存或新的验证体系，也不继续向失败环境加压。

## 方法、边界与准备

- Node 24.20.0、pnpm 12.3.4、冻结 lockfile，隔离 Debian 13 容器；固定 PostgreSQL 16.15 镜像 `postgres@sha256:1beaa3084eee2676f20a9cd9928f0bf2c5bf674f8e49f81017912183d377c61c`。
- 应用 2 CPU / 6 GiB，数据库 1 CPU / 3 GiB，数据库 `network=none`、无发布端口，通过本任务卷的 Unix socket 连接。实际 JWT、HTTP、SQL/RLS、命令消费、持久 FINAL 和派生发布，未连接生产 Supabase。
- 原 70 国父/子来源和 70 份回执均与固定原件匹配。首次离线父开局误用了 2026-10-28，指纹检查发现后废弃；改用 2026-10-29 后完全一致，错误版本未进入数据库。未绕过完整 Core 来源验证。
- 复用既有原生 helper。临时 Docker 适配器只将 helper 的 Linux socket bind 映射为本任务命名卷子目录；临时 pg observer 将原生测试 host 的每池上限 1 调为正式配置的 2，并收集连接等待/持有和事件循环指标。产品文件保持候选提交不变；未调整请求预算、权限或经济规则。
- 70 国 Industry H0 派生准备实际约 588.06 秒，head/event 保持 0；正式 Node 冷启动约 288.91 秒。完整来源准入约 320.56 秒，另有来源重建和安装。均单独计入环境准备，不计入在线延迟。
- 100 个虚拟会话编号由两个真实授权身份承载，不是 100 个独立账户。请求按计划时间持续发送；慢响应后观测到 213 次同一会话仍在途时的新轮询，因此这是约 20 请求/秒的 offered-load 结果，不能称严格“最多 100 个在途请求”的验收。不能通过慢响应自动降低输入来记作通过；后续若采用串行会话，必须将未能按期发出的需求明确列出。
- 读取覆盖 Finance ledger-balances、Social service-pools、Industry industry-labour-current；短对照另含 Central Bank ledger-balances。不是全部 Office 命令、真实 WorldClock、全赛季、长期稳定性、公网或远程数据库 RTT 验收。
- 资源桶在短对照后仍延续至显式规划/单写，短段资源 CPU 样本不可当作纯短读 CPU；上述短读比较使用准确阶段的 HTTP 与池指标。混合资源桶包含在途排空。
