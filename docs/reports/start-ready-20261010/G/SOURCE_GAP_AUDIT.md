## external consumer 的硬阻塞

1. `manual-office-intake-runtime.ts:27–37,111–145` 用模块私有 WeakMap 记录真实构造，绑定 **同一个 intakePool 对象、同一个 clock 对象、同一个 worldId**，并要求 consumer 为 PREPARED/READY。复制对象、另一 request 的 pool、remote worker handle/service-binding JSON 都不会命中。consumer 本身在 executor 构造，也不能让 API isolate 的 WeakMap 获得该对象。
2. 聚合 `snapshotComposition:148–168` 另要求各命令与读共用 readPool/roles/auth.fetch/world pins，clock 已由其 owner freeze，且 nowReal/simTime 为 own data methods。聚合不 freeze/proxy borrowed pool/clock/consumer。不同隔离区可以按同一已批准 clock 来源取值，但不能据此声称 JS identity 相同。
3. manual runtime 构造无条件调用 local/CI-only consumer；有 clock 时，consumer:175–182 又构造 `createLocalNarrowReservationWorker`，后者:106–123 独立保留同类 guard。因此只新增一个 production 外壳、传生产连接但伪填 ci、或只处理第一个 guard 都不构成合法生产路径。
4. consumer:187–231 要求现存同 World/Worker 未过期 lease + durable lineage；manual factories:48–67,168–323 只支持 Captain political capital、CB OMO、Social PLAN，缺 source 必拒绝。这里列的是 dispatch 覆盖，不判断 A/E 拥有的正式 carrier 完整度。
5. PREPARED 不等于已运行：consumer:554–569 必须显式 startPreparation 才能 consumeOnce，且单实例并发防重不代替跨 isolate SQL fencing。HOLD executor 无 start/consume caller。reservation local 准备:399–419 的特定 SQL lease acquisition 不是独立生产续期/恢复 host；durable 顶层的既有 lease 检查也不能省略。
6. workerd roundtrip 用 `tests/support/cloudflare-postgres-workerd-fixture.ts:30–69,99–169` 的 TEST_ONLY 固定 World/本地 Hyperdrive/ci/独立 fixture consume 路径，直接调用 financial/read compositions；它没有运行四路聚合或 external manual Office token，也不是生产开局证据。

FINAL 的限定应精确表述：当前 transport operation/DTO 仍命名 narrow-transfer；SQL mapper 本身未按 commandType 过滤，而是验证 durable identity/scope/receipt 通用字段。本报告没有证明 manual Office FINAL 的协议覆盖或部署可达性，也不把它误报为 SQL 必然拒绝其他 family。
