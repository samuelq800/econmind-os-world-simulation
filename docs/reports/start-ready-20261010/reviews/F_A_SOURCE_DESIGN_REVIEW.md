### Critical later implementation obligations

- Current publisher snapshots a DTO through JSON serialization, which intentionally loses WeakSet brands. V2 must obtain/retain a genuine loader-owned immutable instance; a type assertion of the current clone is not compliance. V1 behavior must remain intact.
- Existing loader imports publisher’s digest function. Introducing a shared assembler must avoid module-initialization cycles; no authority side effect or second digest definition may appear as a workaround.
- Receipt registration identity must remain deployment/provenance-owned, not copied from incoming content. A WeakSet proves issuer provenance only after independent human/source verification.
- The hash DAG must be mechanically tested: stable recordId → complete assembly intent → adopted receipt → seed-source payload/bundle digest → signature. No receipt self hash, final seed/bundle hash or signature may flow backward.
- Positive mechanism fixtures must remain explicitly isolated test evidence. Even valid test signatures do not establish production adoption. Real formal consumption remains blocked until genuine scoped inputs are actually provisioned.
- All six Offices require separate actual source/authentication/command/Worker/receipt/projection and recovery evidence as applicable. Financial source wiring cannot substitute for those role-specific deliveries.
