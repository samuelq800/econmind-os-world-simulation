## Candidate behavior

`scripts/v09-staging-evidence-runner.mjs` is a one-shot, dependency-injected
runner. Its operation order is fixed:

1. Parse the version-controlled non-secret owner contract and run the approved
   URI/runtime policy.
2. Reject a linked Supabase project and locally validate the exact `0001`–`0006`
   manifest/provenance chain.
3. Only then invoke the injected PostgreSQL client factory and connect.
4. Verify the exact admin database role and pristine `world_v2`/role boundary.
5. In one setup transaction, create only the exact NOLOGIN roles and namespace,
   write the target-fingerprint/run-ID marker, apply/release-record migrations,
   execute lease/fence evidence, and establish grants plus forced RLS.
6. Commit, verify Worker/Reader role boundaries, exercise connection-loss
   recovery, then use a fresh client for marker-scoped cleanup.

The public evidence contains the random run ID, exact target fingerprint,
namespace, role names, ordered migration IDs and pass/fail stages. It never
contains a connection URL, password, caught database error text, project secret
or credential material.

## Safety properties

- Policy, linked-project and local-manifest failures invoke neither the client
  factory nor `connect()`.
- The runner accepts the secret admin PostgreSQL URL only from
  `V09_STAGING_ADMIN_DATABASE_URL`; no secret is read from disk or printed.
- A failure before setup commit rolls back the single setup transaction. A
  successful or commit-ambiguous marker is cleaned only through a new client
  that validates the exact run ID, fingerprint, roles, owner and external
  dependency boundary.
- The cleanup path never issues `DROP DATABASE`, `DROP OWNED`, a reset, or an
  arbitrary-namespace command. Scoped schema cascade is permitted only after
  PostgreSQL catalog checks find no user-namespace dependent outside `world_v2`.
- A marker mismatch, missing marker, foreign-owned object, external dependent,
  cleanup failure or client-close failure is reported `FAIL_CLOSED`.

## Covered evidence flow

The candidate records these dedicated checks without changing V09.2 semantics:

- initial acquire, renewal, active second-writer rejection, expired takeover to
  fence `2`, DELETE rejection, TRUNCATE rejection and stale fence rejection;
- crash before commit (connection close rolls back; recovery re-acquires fence
  `1`);
- crash after autocommit (lost acknowledgement retains fence `1`; the active
  second writer is rejected; expiry takeover yields fence `2`; old fence is
  rejected);
- schema ownership, PUBLIC revocation, Worker write-without-delete privilege,
  Reader read-only privilege, and RLS enabled/forced/active checks.
