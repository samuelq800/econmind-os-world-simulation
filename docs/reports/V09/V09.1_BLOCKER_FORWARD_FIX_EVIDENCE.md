## Remediation boundary

`0006` installs PostgreSQL `BEFORE DELETE` and `BEFORE TRUNCATE` triggers on
`world_v2.world_writer_lease`. Both raise a deterministic failure, so a
Worker-authorized DML path cannot erase the persisted `fencing_token` lineage.
The existing `0005` guarded INSERT/UPDATE transition remains unchanged.

The corrected path is intentionally not a literal delete/reacquire sequence:
DELETE and TRUNCATE must fail. A normal post-expiry takeover is still permitted,
returns a higher fence, and the old holder/fence commit assertion is rejected by
the database guard with `WORLD_WRITER_FENCE_STALE`.
