## Blocker — broad cascade cleanup

The reviewed runner issued `DROP SCHEMA world_v2 CASCADE`. PostgreSQL cascade
semantics can remove dependent objects outside the disposable namespace. The
prior catalog check was therefore not a sufficient authority boundary for a
one-shot runner.

Required forward correction: enumerate only the objects created by the known
`0001`–`0006` chain and the runner marker, remove them in reverse construction
order with `RESTRICT`, and stop with `CLEANUP_INCOMPLETE` on a marker mismatch,
unexpected object, external dependency, role residue, or any failed teardown

database-level cleanup is acceptable.

## Major — acknowledgement-unknown and evidence durability

The reviewed runner treated a client ending after `COMMIT` as sufficient proof
of an acknowledgement-unknown outcome, and it did not atomically persist the
redacted evidence at an owner-specified local path.

Required forward correction: use a dedicated non-production protocol in which
the primary sends `COMMIT; SELECT pg_sleep(...)`, an independent admin/recovery

cleanup. Missing privileges or an unobservable exact backend must report
`CRASH_PROTOCOL_UNAVAILABLE`, not a pass. The runner must write redacted
evidence by temp-file plus atomic rename at the approved local path; a write
failure must fail closed without weakening the database-cleanup obligation.
