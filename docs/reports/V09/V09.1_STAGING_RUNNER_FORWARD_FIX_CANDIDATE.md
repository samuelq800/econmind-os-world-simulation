## Narrow forward correction

- Cleanup no longer has `CASCADE`, `DROP DATABASE`, `DROP OWNED`, reset, or
  cross-schema deletion behavior. Before mutation it binds the exact run ID,
  fingerprint, roles, migration-owner identity, schema ownership, allowlisted
  inventory, role attributes/memberships, standalone object absence, and all
  external dependents.
- It drops policies and then the known `0006` through `0001` objects in reverse
  construction order, including the two 0003 constraints and the runner marker.
  Every schema/object drop uses `RESTRICT`; each named role can be dropped only
  after its exact membership is revoked and no shared dependency remains.
  Unexpected inventory, public/operator or other external dependents, residue,
  or any teardown failure reports `CLEANUP_INCOMPLETE`.
- The acknowledgement-unknown path is now a real dedicated-staging protocol:
  the primary transaction marks the exact run, sends
  `COMMIT; SELECT pg_sleep(...)`, and is observed by an independent recovery
  connection in `pg_stat_activity` as the exact PID, active `PgSleep`, and
  protocol-marked query before that exact PID is terminated. The pre-commit
  branch must recover the exact marker as `PENDING`; the acknowledgement-lost
  branch must recover that same exact marker as `COMMITTED`.
  Permission/visibility/protocol failure reports `CRASH_PROTOCOL_UNAVAILABLE`.
- The runner writes redacted local evidence only to the approved absolute path
  in the versioned owner contract. It writes a `0600` temporary file, syncs it,
  atomically renames it, and syncs the parent directory. A write failure changes
  the result to `FAIL_CLOSED` with `DURABLE_EVIDENCE_WRITE_FAILED`; it occurs
  after the runner has attempted the same strict cleanup.

## Focused local evidence

The policy/runner test suite uses a shared, transaction-aware fake PostgreSQL
state. It covers:

- rollback of a pre-commit lease when its client ends;
- a committed marker plus lost acknowledgement only after the controlled
  post-commit sleep/PID termination sequence;
- unavailable termination permission as `CRASH_PROTOCOL_UNAVAILABLE` with
  cleanup still attempted;
- a synthetic public-operator external dependency that prevents any cleanup
  drop and remains present;
- cleanup and durable-evidence failure paths that remain fail closed; and
- redacted temp-and-rename local evidence output.

These are implementation tests only. The fake proves control flow and failure
handling; it does not replace the dedicated non-production PostgreSQL evidence
run, whose permissions and `pg_stat_activity` semantics must be independently
observed after fresh review.
