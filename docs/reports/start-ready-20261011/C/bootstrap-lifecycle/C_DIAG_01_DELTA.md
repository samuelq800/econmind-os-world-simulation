## Local defect and correction

The rejected parent called its close-observation promise `exited`. `waitForOutput` detected the parent exit and then awaited that promise without a deadline. An inherited pipe could keep `close` pending, preventing both error delivery and caller `finally` cleanup. The C wrapper also awaited `close` before reaching its KILL fallback and evidence finalization; its 150-second timer sent only TERM. B demonstrated this exact ordering defect. No product-launcher change is justified by that demonstration.

This revision separates the observations and keeps failure paths bounded:

1. `observeCommand` records **exit** separately from **close/drain**. READY failure drains only until the already established wait deadline; `waitForExit` similarly shares its existing deadline between exit and drain. Diagnostic text retains original nonzero exit/signal, available output and `drain:complete/timed-out`. No original READY, TOCTOU, startup, exit or cleanup timeout is increased.
2. Caller cleanup retains the primary failure. If cleanup also fails, an AggregateError contains both original and cleanup errors, with both messages visible. Its caught cleanup exception remains `cause`; the original remains the first member of `errors`. The Web-only resource cleanup attempts all four independent actions with `allSettled`; it no longer ignores an exit/drain error or skips another resource merely because one cleanup action failed.
3. The wrapper awaits parent exit only until its unchanged 150-second run deadline. Parent exit permits only a finite 2000 ms drain grace. Expired run/drain or observed leftovers reach TERM→KILL without requiring `close`. Actual wrapper TERM grace remains 2000 ms and post-KILL allowance remains the original 250 ms. A final finite drain check, local read-handle destruction and child-handle unref prevent an open pipe/failed cleanup from making finalization wait indefinitely.
4. Wrapper evidence records original exit, run/drain/cleanup timeout separately, signals, available raw output, observed ownership, remaining rows and observation errors. Nonzero exits, drain timeouts, cleanup failures and errors cannot become PASS because cleanup succeeded. Unknown/unobserved pipe holders are not killed; zero _observed_ leftovers is not proof that every short-lived descendant was sampled.
5. New C-owned `control-output-pipe.mjs` supplies only ordinary local Node controls: a parent exits while its observed child retains inherited output and ignores TERM; a fast exit fully drains stdout/stderr; and a TERM-resistant parent/child reach the wrapper's own runtime deadline. The child naturally self-terminates after 4000 ms and the runtime-deadline parent after 4200 ms if owned cleanup does not act first. These are test-only safety timers, not a World Clock/economic timer. No service/network/database is used by these six added cases.

Only the existing lifecycle test, C wrapper and new C control/evidence documents change. `scripts/run-development-stack.mjs`, `scripts/run-development-service.mjs`, original `tests/fixtures/control-bootstrap-service.mjs`, manual fixture, O reports, Core/SQL/grants/status and other-owner files remain unchanged. Existing 14 cases remain, including the original READY-once, crash, TOCTOU and forced-cleanup failure assertions. No skip, blanket retry or product source patch is added.
