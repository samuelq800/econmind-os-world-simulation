# World V2 地理推导与人文开局情景

这是一份可复现的世界设计候选，不是正式赛季初始状态。

## 本次修改

- 依据官方手册 v1.1 第22、90页，将可开发地质资源限定为原油、天然气、铀、铁矿石、铜、锂。保留320个地理点，其中240个矿床候选、42个粮食农业点、38个未启用背景点。粮食不算地下资源，背景资源不新增商品。
- 六类矿产按地形与降水代理、空间地质区和供应分散约束重配。锂48处、45国；铀16处、15国。这些是候选地质模型，不是卫星图像能直接测得的地下事实。
- 70国划分122个经济区域。区域以国土条带作为简化结算单元，叠加气候、山脉与水域；不是已经划定的行政区或精确流域。
- 人口先以农业和水承载生成世界总量，再按交通节点、河谷、耕地与资源腹地重新分布。城镇比例、技能与住房为人文地理情景假设，不是地形必然决定的历史。
- 350个设施候选按聚居潜力重新分布，每国2–9个。项目编号对应Core现有PROJECT-XX目录；能力有单位，但尚未建成投运，配方系数未绑定。
- 349条连接覆盖全部350个设施候选。它们是待勘测通道，直线穿水处明确要求港口/渡运，跨境处要求过境许可，不能作为已可通行道路。电网单独建表，不从海运线推导跨境供电。
- 地质原始量、已采、地下剩余、发现/可采/开发层次分别记录，后三者是包含关系。公开包中的矿床全部明确为公开情景候选，不包含所谓未发现的秘密矿藏。
- 海域重叠区冻结资源开发直到有划界或登记共同开发安排。开发、经营、过境、港口使用、通航和共享淡水分别设定权利条件。

## 五份底表

1. world-space.json：统一比例尺、122个区域、土地用途、气候、水量、聚居条件。
2. natural-endowment.json：矿床数量与开发条件、71组简化水系归集、气候模板。
3. opening-society.json：人口、技能、住房、粮食缓冲、现金和银行情景、具名设施候选。
4. connections-rights.json：货运候选网络、电网、独立使用权。
5. initialization-validation.json：源文件哈希、模型系数、供需诊断、最终平衡缺口与启用阻塞项。

CSV为同一数据的展开摘录；JSON保留完整嵌套记录。

## 数值从哪里来

所有结果由 tools/derive_geographic_world.py 计算，输入是既有地图分区和修改前快照。
代码中的常数是明确提出的虚构情景系数，不是手册固定参数或地球实测值。

- 距离：像素距离 × 36000 / 1774；面积：像素面积 × 比例尺平方。
- 高程：距海距离和已画山脊构造的合成高程，没有DEM。
- 降水/温度：14类气候的模板加权；月降水采用季节项。
- 径流：面积 × 年降水 × 随合成高程变化的径流系数；65%预留生态径流。
- 农业：可用土地和水约束取小，再乘气候单产；实际农业模块仍须由Core明确唯一责任。
- 人口：先推导承载总量，按交通/河流重力、可耕地和矿区聚居权重重新分配；没有凭空增加总人口。
- 地质：候选勘探面积 × 各资源丰度系数 × 环境适合度；地下量敏感范围0.25–4倍。图像不能确定岩性、品位和真实储量，因此保留质量代理与不确定性。
- 运输：候选通道长度、模式与聚居需求推导容量、时间。还没有完成可通行路网与实际货流分配。
- 历史债务、既有合同与技术许可采用明确的空白开局假设。不能从自然环境推断这些历史事实。

## 最后平衡

自然禀赋和人文人口先固定，再检查粮食、水、住房、劳动力、电力、运输和资金条件。
不会为了消除短缺而改写原始地质总量、平均人口或增加隐藏国家乘数。
当前显示常态、气候枯水与蓄水灌溉恢复能力诊断；恢复方案要求实际建设、投资、人员与水权。
完整12部门生产、运输、合同与600模拟日运行测试尚未执行，不能宣称世界已经能够正式开局。

validation-result.json 记录结构/守恒校验结果与缺口数量。生产接入必须另外完成Core农业责任、配方系数、经济体绑定、权限、运输及正常/阻断/恢复验收。
